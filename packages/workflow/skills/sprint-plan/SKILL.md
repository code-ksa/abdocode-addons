description: Plan and execute a project in measurable sprints with an explicit database choice.
---
Understand the user's requested outcome, then divide it into ordered sprints with deliverables and acceptance checks. In full access, create a new project only when requested using project-create and an English ASCII folder name; report the actual returned path. In restricted modes obtain the required scope/location. Respect the user's database choice; use SQLite only if no database was specified. For a Next.js foundation include a layout, stylesheet import, coherent responsive interface, database schema and build checks. Inspect the running page and its styles rather than declaring success from HTTP 200. Do not claim CRUD is complete when only a static scaffold exists. Continue or stop according to the user's scope, not an invented approval requirement.
